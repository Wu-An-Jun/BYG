# BYG

BYG 是本次行动的代号。本仓库作为行动的统一版本管理入口，各子项目保留独立的知识体系、计划、记录和协作规则。

## 项目结构

```text
BYG/
├── README.md          # 行动总入口与 Git 使用说明
├── AGENTS.md          # 仓库级协作与安全边界
├── .gitignore         # 本地配置、密钥、临时文件和备份的忽略规则
├── .gitattributes     # 文本文件换行规则
├── 408/               # 408 子项目（首次仅在本地，待确认公开范围）
└── math/              # 数学子项目（首次仅在本地，待确认公开范围）
```

Git 只在 BYG 根目录初始化，子目录不重复创建仓库。子目录中的教学规则各自生效，不能因为统一版本管理而混合学科内容或覆盖彼此状态。

## 首次提交范围与隐私

首次提交只包含仓库入口和管理配置，不包含个人原始作答、学习记录、掌握度数据或历史备份。

目标 GitHub 仓库当前为公开仓库。纳入学习资料前须确认公开范围，检查个人信息、账号信息和访问凭据；不要把“本地提交”与“公开推送”混为一谈。

远程名称为 `origin`，主分支为 `main`。本机 SSH 认证尚未通过，当前使用 HTTPS 连接同一仓库，凭据由 GitHub CLI 管理；不将访问令牌写进文件或远程 URL。

## 日常版本管理

先查看变化，再按本次任务精确选择文件：

```bash
git status --short
git diff
# 使用实际需要的文件路径，不无差别添加其他任务的改动：
git add <file-path>
git diff --cached --stat
git diff --cached
git commit -m "docs(408): update daily study records"
git push
```

`<file-path>` 是需要替换的占位符，不是可以原样运行的命令。

本地提交用于保存快照；推送用于同步远程。未确认可公开的内容不得推送到公开仓库。不自动运行定时提交或自动推送。

## 提交约定

建议一次提交只处理一个主题，例如：

- `docs: update BYG overview`
- `docs(408): update daily plan and evidence`
- `docs(math): update progress records`
- `chore: maintain repository settings`

不强制改写既有历史。已经推送的错误通过后续修正提交处理；不要随意强推、重置或删除学习记录。

## 数据维护原则

- 原始答案、出题前预测、事后批改和状态更新要能区分。
- 预测不得在看到答案后回填或改写为“事前预测”。
- 任务完成与知识掌握分别记录，不能用文档变更次数代替学习进度。
- 不上传环境文件、密钥、令牌、临时文件或重复的本地压缩备份。
- Git 忽略规则不删除本地文件，也不会追溯清除已经提交过的敏感信息。
