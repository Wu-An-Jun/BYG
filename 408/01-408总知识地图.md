## E. 四科之间必须建立的连接

| 连接 | 必须理解的共同问题 |
|---|---|
| Cache ↔ 虚拟内存/TLB | 局部性、地址转换、命中与缺失、性能代价 |
| 中断 ↔ 操作系统系统调用/I/O | 硬件事件如何进入内核并完成处理 |
| CPU 性能 ↔ OS 调度 | 执行时间、上下文切换和调度开销如何影响性能 |
| 栈/队列/树/图 ↔ OS/网络 | 调度队列、页表/文件树、路由与搜索都依赖数据结构思想 |
| 进程/线程 ↔ TCP 端口 | 进程并发、端口寻址、连接状态和资源管理 |
| 磁盘/SSD ↔ 文件系统/I/O | 存储介质性能如何影响文件分配和设备调度 |
| 分层封装 ↔ 系统调用/中断 | 上层请求如何经过协议栈和硬件完成一次通信 |
| 复杂度 ↔ 性能指标 | 算法复杂度与硬件/系统常数共同决定实际效率 |

## H. 三条跨科综合理解链

1. **运行一个程序**：源代码 → 指令与调用栈 → 进程地址空间 → 页表/TLB → Cache/主存 → CPU执行 → 中断与调度。
2. **保存一个文件**：系统调用 → 文件描述符/目录/inode → 文件块映射 → 缓冲与驱动 → DMA/中断 → 磁盘或SSD。
3. **访问一个网页**：域名解析 → 路由与ARP → TCP连接 → HTTP请求 → 分层封装 → 链路发送；题目给定的网络与HTTP版本优先。

每条链要能够解释“谁维护状态、地址在哪转换、数据在哪排队、失败会在哪里处理”。它们是综合理解训练，不替代单节点计算练习。
