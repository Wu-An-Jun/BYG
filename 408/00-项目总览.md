# 00｜项目总览：如何把 408 学成一张能做题的地图

## 一、项目目标

把 408 四门课从“章节目录”变成三层系统：

1. **知识层**：知道每章有哪些概念、公式、算法、协议和边界。
2. **机制层**：知道概念之间为什么连接，能从系统过程解释题目。
3. **得分层**：能在选择题和综合应用题中完成计算、判断、证明思路和算法表达。

真正的目标不是把所有内容看过，而是形成以下能力：

- 看到题目能判断属于哪个知识节点。
- 能把题目还原成定义、条件、过程和结论。
- 能发现选项或推导中的边界错误。
- 能把算法写成可执行的 C/C++ 思路。
- 能在跨章节、跨学科题目中保持稳定。

## 二、四科主线

### 数据结构：从抽象结构到算法正确性

`复杂度与代码表达贯穿全程；线性结构 → 树/图 → 查找/排序`

核心问题：数据怎么组织、操作如何实现、算法为什么正确、复杂度是多少。

### 计算机组成原理：从信息表示到硬件执行

`数值表示 → 运算 → 存储层次 → 指令 → CPU → 流水线 → 总线与 I/O`

核心问题：一个程序如何被表示、取指、执行、访问存储器，并受到性能瓶颈限制。

### 操作系统：从程序运行到资源管理

`运行环境 → 进程线程 → 调度 → 同步互斥 → 死锁 → 内存 → 文件 → I/O`

核心问题：多个程序如何安全、有效地共享 CPU、内存、设备和文件。

### 计算机网络：从比特传输到应用服务

`物理传输 → 成帧与可靠传输 → 路由与 IP → TCP/UDP → DNS/HTTP/FTP/邮件`

核心问题：数据如何分层封装、如何到达目的地、如何保证可靠性和控制拥塞。

## 三、学习闭环

每个知识点必须经过以下循环：

```text
定位节点 → 闭卷回忆 → 最小讲解 → 典型题 → 错误归因 → 隔天复测 → 一周混合复测
```

### 错误归因不能只写“粗心”

统一归类为：

- 概念缺失：不知道定义或适用条件。
- 概念混淆：把两个相近术语当成同一个。
- 过程断裂：知道结论，但不能解释中间步骤。
- 计算失误：单位、进制、边界、指数或代数出错。
- 题型迁移失败：原题会做，换问法就不会。
- 表达失误：思路正确，但算法、公式或术语写不出来。
- 时间管理：会做但没有在规定时间内完成。

## 四、每个知识点的完成标准

| 层级 | 最低证据 | 状态 |
|---|---|---|
| 识别 | 能说出定义、对象和关键词 | 🟡 恢复中起点 |
| 解释 | 能说明机制、步骤和边界 | 🟡 恢复中 |
| 应用 | 能独立做典型题/算题/写算法 | 🟢 已验证候选 |
| 迁移 | 不同问法、不同数字、混合章节仍能做 | 🔵 稳定掌握候选 |
| 稳定 | 一周后复测，且错题能解释为什么错 | 🔵 稳定掌握 |

## 五、时间与计划的约束

项目已有对话提到“90 天备考”，但目前没有把目标院校、目标分数、每天可用时长、其他科目占用时间写入可验证档案。因此在这些信息确认前，不把 90 天拆成精确到每天的承诺计划，只执行已经有证据支持的下一步任务。

计划优先级按以下顺序决定：

1. 跨天掉点：昨天会、今天不会。
2. 对后续学习依赖较强、可检验的基础节点。
3. 后续章节的前置依赖。
4. 真题暴露出的重复错误。
5. 新内容扩展。

## 六、负责人的底线

- 不以看课时长代替掌握证据。
- 不以一次正确代替跨天稳定。
- 不把不会的内容用“以后再说”无限延期。
- 不为了覆盖目录而牺牲核心题型训练。
- 不把非 408 内容塞进主计划造成注意力稀释。
- 遇到大纲变化，先复核范围，再更新地图。

## 数据口径

本文件为教学方法概述。状态以 `学习记录/掌握标准与复测协议.md` 的 U/F/R/V/S 与 CSV 主表为准；历史分值与命题范围以 `资料与范围核验.md` 的核验边界为准。不能将“做过一次典型题”单独视为V，也不能由一题覆盖整个宽节点。
